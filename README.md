# Кофейня на двоих — прототип MVP

Асинхронный кооп на двоих для Telegram Mini App: вместе ведёте кофейню, на выручку обустраиваете квартиру над ней и заводите кота. Концепт: «Наше место» (документ в проекте Telegram Games).

**Играть в браузере:** https://grigory2508.github.io/coffee-for-two/

> Один раз нужно включить Pages: Settings → Pages → Source: **Deploy from a branch** → ветка **gh-pages**, папка **/(root)**. Сборку в эту ветку выкладывает workflow при каждом пуше в `main`.

## Что есть в прототипе

- **Две роли.** **Бариста** обслуживает гостей и убирает столики. **Управляющий** ездит к поставщику, ведёт меню, расширяет кофейню и запускает рекламу. Одна активная роль на игрока. Перейти в роль со свободным местом можно самому, если ты не последний в своей роли; поменяться с конкретным человеком — только по взаимному согласию (с соседом-NPC — сразу).
- **Смена баристы** — мини-игра на 75 секунд: у стойки один гость, следующий подходит, когда этого обслужили (терпение считается от подхода к стойке, остальные ждут в очереди). Гость пьёт здесь или берёт с собой: сначала ставишь чашку или бумажный стакан (стаканы — позиция склада), потом тапаешь ингредиенты — чашка в разрезе показывает слои рецепта в пропорциях. Эспрессо и пенка готовятся с таймером, Кофемашина Pro даёт второй рожок. «Подать» всегда на одном месте. Кто пьёт здесь — садится за столик (4, с верандой 6), после него столик надо протереть. Смена стоит 1 силу.
- **Меню дня.** Управляющий открывает напитки и выбирает до 6 в меню дня — гости заказывают только их, а на станциях у баристы только нужные ингредиенты. Каталог может расти сколько угодно.
- **Интерфейс.** Сверху закреплены рейтинг, деньги, свои силы и тревога «мало продуктов». Четыре вкладки: своя по роли (бариста — «Стойка», управляющий — «Дела»: склад, меню, развитие), «Кофейня» (цель, рейтинг недели, цифры, истории, журнал), «Квартира», «Команда» (заявки, роли, просьбы, записки). «Пока тебя не было» — лист при входе.
- **Дела управляющего** — поездка к поставщику (корзина из нескольких товаров), улучшение или расширение (веранда: +2 столика, +1 гость), реклама (+гости на 3 смены). Каждое дело — 1 сила; новые напитки в меню — бесплатно. У обоих по 3 силы, одна восстанавливается за 4 часа.
- **Постоянные гости.** У троих гостей истории по 5 визитов. Каждую сцену видит только тот, кто стоял за стойкой; напарник видит «это слышал(а) Аня — спроси».
- **Ворота 1 → квартира над кофейней.** Нужны рейтинг 3★ и 8 смен. В квартире 24 предмета декора в 8 местах и кот: его надо кормить и гладить, кот в хорошем настроении приходит в кофейню и даёт +10% чаевых.
- **Команда до 5 человек.** Бариста — до 4, управляющих — до 2, всегда хотя бы по одному (пустую роль прикрывает сосед Артур; он же подхватывает роль, если все её люди не появлялись сутки). Позвать может любой сотрудник: человек открывает ссылку, выбирает свободную роль и подаёт заявку; бот сразу пишет всем сотрудникам, а принимают, когда одобрили все. Заявка живёт 48 часов. Касса одна: пока кто-то на смене, другой бариста видит «касса занята». Кабинет тоже один: он занят, пока управляющий держит открытым «Управление» (освобождается через 3 минуты без действий). Создатель может убрать сотрудника, остальные могут выйти и открыть свою кофейню.
- **Связь между напарниками.** Доска записок со стикерами, сводка «Пока тебя не было», журнал событий. Кнопки «Попросить напарника» отправляют карточку в вашу переписку.
- **Рейтинг кофеен недели.** Очки за довольных гостей; если оба напарника работали в этот день — ×1.2. Соседи по рейтингу пока сгенерированные.
- **RU и EN.** Язык берётся из Telegram, переключается в отладке.
- **Отладка (🛠).** Промотка времени на +1ч/+4ч/+1д/+1нед (только в локальном режиме), «силы и +1000 🪙», вкладка нового сотрудника, сброс.

## Как поиграть вдвоём без сервера

Локальный режим хранит кофейню в `localStorage` браузера. Поэтому команда в нём — это несколько вкладок одного браузера:

1. Откройте игру и откройте кофейню.
2. 🛠 → «Вкладка нового сотрудника» — откроется вкладка другого игрока со ссылкой-приглашением; он подаёт заявку, а вы одобряете её в первой вкладке.
3. Играйте по очереди: всё, что делает один, сразу видно другому.

Чтобы играть с двух телефонов, нужен сервер (ниже).

## Устройство

```
src/core/        логика игры: чистые функции, общие для клиента и сервера
  content.ts     весь контент и баланс (напитки, цены, декор, гости, CONFIG)
  engine.ts      команды (apply), время (advance), смена, NPC, ворота, сводка
src/net/         Backend: LocalBackend (localStorage + BroadcastChannel) и RemoteBackend (API)
src/platform/    Telegram WebApp, часы с промоткой, личность игрока, аналитика PostHog
src/ui/          интерфейс на Preact, SVG-заглушки вместо арта
supabase/        сервер: SQL-схема, функции api (команды) и bot (вебхук + сводки)
scripts/         sync-server (копия ядра на сервер), e2e (прогон двух игроков в Playwright)
```

Состояние кофейни — один JSON. Клиент и сервер применяют одни и те же команды из `src/core/engine.ts`. Сервер хранит строку на кофейню и защищает её от одновременной записи двух напарников через версию.

Баланс собран в `src/core/content.ts` (`CONFIG`, цены, рецепты) — менять цифры там.

## Команды

```bash
npm install
npm run dev          # локально на http://localhost:5173
npm test             # тесты ядра (vitest)
npm run build        # сборка в dist/
npm run sync-server  # скопировать src/core в supabase/functions/_shared/core (после правок ядра!)
node scripts/e2e.mjs # прогон двух игроков (нужен playwright и запущенный `npx vite preview --port 4173`)
```

Каждый пуш в `main` прогоняет тесты, проверяет, что ядро на сервере совпадает с клиентским, и выкладывает сборку на GitHub Pages.

## Подключение бота и сервера

Сервер выкладывает GitHub: workflow **Deploy server** (`.github/workflows/server.yml`) задаёт секреты функциям Supabase, деплоит `api` и `bot`, вешает вебхук бота и проверяет, что API отвечает. Локально ставить Supabase CLI не нужно.

1. **BotFather:** `/newbot` (токен), `/newapp` (URL `https://grigory2508.github.io/coffee-for-two/`, короткое имя `play`, картинка — `bot-assets/app-cover-640x360.png`), `/setinline` (инлайн-приглашения).
2. **Supabase:** создать проект, выполнить `supabase/migrations/0001_init.sql` в SQL Editor, создать Access Token (Account → Access Tokens).
3. **GitHub → Settings → Secrets and variables → Actions:**

   | Тип | Имя | Значение |
   | --- | --- | --- |
   | Secret | `SUPABASE_ACCESS_TOKEN` | токен из Supabase |
   | Secret | `BOT_TOKEN` | токен бота |
   | Secret | `WEBHOOK_SECRET` | случайная строка из букв, цифр, `_` и `-` |
   | Secret | `CRON_SECRET` | другая случайная строка |
   | Variable | `SUPABASE_PROJECT_REF` | ID проекта (`https://<ref>.supabase.co`) |
   | Variable | `BOT_USERNAME` | имя бота без @ |
   | Variable | `APP_SHORTNAME` | `play` |
   | Variable | `ALLOW_DEBUG` | `1` на время теста |

4. **Actions → Deploy server → Run workflow**, затем **Deploy to GitHub Pages → Run workflow** (адрес API соберётся из `SUPABASE_PROJECT_REF`).
5. **Сводки раз в час:** включить расширения `pg_cron` и `pg_net` и выполнить `cron.schedule` из конца файла миграции.

Адрес API: `https://<ref>.supabase.co/functions/v1/api`, бота: `https://<ref>.supabase.co/functions/v1/bot`.
